# 対応規則 — 正式な定義の節から、モデルの要素へ

**左列は正式な定義（業務知識・コアドメイン）の節、右列はこの資料で使う場所である。** 左列に無いものは候補にならない。これが「正式な定義に無い語を要素にしない」を表の形で守る仕組みである。

| 正式な定義の節 | モデル要素の候補 | 割り当ての判定 |
|---|---|---|
| ユビキタス言語 > 業務用語 | 値オブジェクト／エンティティ／集約ルート | 属性が同じでも**同一性**で区別する（識別子を持ち、状態が変わっても同じものとして追う）→ エンティティ。**値**で区別し、自分の制約を生成時から守る → 値オブジェクト。複数の概念を**1つの不変条件で束ねる境界**の根 → 集約ルート |
| ユビキタス言語 > 業務イベント | ドメインイベント | この文脈の集約の操作の事後条件として起きるものは、判断を始めるかどうかに関わらずすべてドメインイベントにする（別の文脈が購読しうる）。集約の操作が発さないもの（別の文脈の事実、導出結果の言い換え）は載せず、「捨てた割り当て」に理由を書く。イベントは通知であって事実の置き場ではない。事実は集約が持つ |
| 概念 | 集約の境界 | 概念の説明に「まとまり」「属する」「持つ」が現れる関係が、境界の候補になる。1つの操作で一貫させたい範囲を最小にする |
| 常に守られること | 各要素の不変条件 | 1つの要素の内側で守れる → その要素の不変条件。複数要素にまたがる → 集約の不変条件（＝集約境界を引く根拠）。どの集約でも守れない → 「集約をまたぐ不変条件」として守る場所を書き、決まらなければ未決 |
| 状態と、その移り変わり | 状態と型の分割 | 状態ごとに呼べる操作が違うなら型を分ける（不正な操作を呼べなくする）。違わないなら分けない。引き金（起きること）は操作の候補 |
| 誰が行えるか | 操作の呼び手（要素にしない） | アクターを型にしない。「行える役割」は操作の事前条件（呼び手が本人であること等）に、「行えない場合の業務上の理由」は拒む理由に写す |
| 業務ルール | 操作の事前条件・事後条件 | 成立条件 → 事前条件。成立後の状態 → 事後条件。境界値は事前条件の中に具体値で書く |
| 導出されること | 操作の事後条件、または呼び手の手順 | 条件から一意に決まる計算は、それを持つ要素の操作の事後条件に。集合に対する手順（並べる・選ぶ）は1件の要素ではなく呼び手の側に置く |
| 同時に起きたとき | 集約をまたぐ不変条件、または未決 | 「どちらが通るか」は業務の決まりなので不変条件に写す。「どう保証するか」は設計の関心なので未決か「書かないもの」に送る |
| 拒むときの理由 | 操作の拒む理由 | 拒まれる操作 → その操作の行。拒まれる業務上の根拠 → 拒む理由の欄に、業務知識の語のまま書く |
| BDD | BDDとの対応（検証材料） | 各シナリオが、どの要素のどの操作と不変条件で成立するかを対応表にする。対応しないシナリオがあれば要素が足りず、対応しない要素があれば要素が余っている |
| まだ決まっていないこと | 未決 | 未決が残る要素は候補のままにし、確定に見せない。何が分かれば確定するかを書く |

## 判定の例

**同一性か、値か。** 「予約」は、状態が変わっても予約番号が同じなら同じ予約として追う → エンティティ。「利用枠」は、同じ会議室・同じ時間帯なら誰が持っていても同じもの → 値オブジェクト。判定の問いは「属性が全部同じ2つを、別物として扱う場面があるか」である。あればエンティティ、無ければ値オブジェクト。

**識別子だけでは集約にならない。** 「顧客の予約資格」は顧客ごとに決まるが、この文脈に顧客の登録・退会（ライフサイクル）は無く、顧客は識別子の値としてしか現れない。資格は「その顧客の予約で無断不利用がいつ起きたか」と判定時刻から決まる値で、無断不利用が起き、時が経てば決まる値が変わるだけで、資格自身が遷移するのではない → 値オブジェクト。無断不利用という事実は確定予約で起きるので、予約（集約）が持つ。資格は「誰の資格か」を表す顧客の識別子を値の一部として持ち、予約の生成の条件で「資格の顧客＝予約者」を確かめる。判定の問いは「その文脈で、そのものの生成から終端までを扱うか」「他の事実から導出し直せるか」である。前者が偽で後者が真なら、値オブジェクト。

**集約の境界。** 「予約は一人の予約者と一つの利用枠に属する」は予約の内側で守れる → 予約の不変条件。「同じ会議室の重なる利用枠へ有効な予約は一つ」は複数の予約にまたがる → 予約の集約では守れない。会議室を集約にする案と、予約の生成の条件として外に出す案があり、正式な定義に会議室の決まりが無ければ後者を採る。

**型の分割。** 「仮押さえ予約」は確定できるが「確定予約」は確定できない → 呼べる操作が違うので型を分ける。「繰上済み予約待ち」と「取消済み予約待ち」はどちらも操作を持たない → 分けず、どちらで終わったかを値で持つ。

**アクターは型にしない。** 「予約を取り消せるのはその予約の予約者」は、取り消す操作の事前条件「呼び手が予約者本人」と、拒む理由「他人の予約の取消」に写す。「予約者」という要素は作らない。

**集合への規則。** 「予約待ちの繰上げ順は受付日時と予約待ち番号で決まる」は、1件の予約待ちの性質ではない。「予約待ち列」を要素にする案は、正式な定義にその語が無ければ採らず、繰上げ判断（イベントの受け手）の手順として書く。
