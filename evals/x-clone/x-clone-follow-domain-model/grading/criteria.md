# X のクローンのフォローに固有の条件

フォローの業務知識は、フォローを外すとそのフォローが終わり、同じ相手をもう一度フォローすると新しいフォローが生まれる、と決めている。一件のフォローが短い生涯を持つので、二人の間の重複の禁止とフォロー上限は、一件のフォローの外に出る規則になる。この条件は、その読み取りと、隣の業務の事実の扱いを判断の型にしたものである。

### follow-pair-rule-outside

重み: 3

業務知識の「常に守られること」にある、同じフォロワーと同じフォロー相手の間のフォロー中のフォローが一つであることを確かめる。

PASS：この規則を一件のフォローの内側で守れないものとして扱い、呼び手が渡す事実で拒むか、集約の外の誰が守るかを書いている。同時に二度フォローしたときに誰が保証するかも、役割の言葉で書いている。

FAIL：二人の間の組を一つの集約にして、終わったフォローと新しいフォローを同じ件として扱っている（業務知識の「新しいフォローが生まれる」と食い違う）。または、この規則の守り方も守り手も書いていない。

### follow-limit-by-count

重み: 3

PASS：フォロー上限は、業務知識の語（フォロー中の人数など）で表した値をフォローするコマンドが受け取って判断する形か、集約の外の守り手を書く形で扱われ、一人の利用者のすべてのフォローを内側に持つ集約を作っていない。上限の手前で同時に二人をフォローしたときに誰が保証するかが書かれている。

FAIL：上限を守るために、一人の利用者のフォロー全体を一つの集約にしている。または、上限の判断に使う値も守り手も書かれていない。

### follow-ended-not-revived

重み: 2

PASS：状態遷移図と本文は、業務知識のとおり、フォローを外すとそのフォローが終わり、もう一度フォローすると新しいフォローが生まれる形になっている。業務知識に無い「外した」「フォローしていない」のような状態を、集約の状態として描いていない。そうした状態が要ると考えたなら、業務知識への提案に回している。

FAIL：外したフォローが状態として残り、もう一度フォローすると同じフォローが戻る形を、提案として示さずに図か本文に描いている。

### follow-foreign-facts

重み: 2

業務知識では、利用者の登録と利用者IDはアカウントの業務が持ち、フォロー相手が登録済みの利用者であることはフォローの成り立つ条件である。

PASS：登録済みかどうかは、フォローする業務の外の事実として、呼び手が渡すか確かめる形で扱われ、利用者を集約やエンティティにしていない。「利用者登録を終えていない人」「存在しない利用者」の拒む理由を、どの段階で拒むかとともに書いている。

FAIL：利用者をこの文脈の集約かエンティティにしている。または、登録済みかどうかの判断の仕組みを、業務知識に無い決まりとしてモデルの側で作っている。
