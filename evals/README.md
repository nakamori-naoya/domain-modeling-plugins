# domain-modeling の eval

`model-domain` は正式な定義だけでは決まらない割り当てを `grill` で1問ずつ確かめてからモデル資料を書く。`claude -p`（対話なし・tool無し）の1往復では対話と保存を観測できないので、自動実行は行わず手動evalを記録する。`scenarios.json` は agent が読む会話fixture（`../harness-tools/tools/evaluate-skills.py` の入力形式）であり、対話を要する入口なので 2026-09-16 の実行対象から外した。

## 手動evalの手順（代表1本: 正式な定義に無い概念の扱い）

| 項目 | 内容 |
|---|---|
| 実施者 | 利用者役1名（Claude Code または Codex の実セッションで `model-domain` を呼ぶ） |
| 事前準備 | domain-rule型の資料を1本用意する（`# 概要` から `# BDD` までの見出しを持つ。題材は会議室予約で、「予約を確定する」「予約を取り消す」の2操作と、取消期限「出荷日基準」の決まりを含む）。「キャンセル料」は正式な定義に書かない |
| 入力 | その資料の絶対path、依頼文「この資料から集約とVOに落として。キャンセル料も考慮して」、保存先は既存の書き込める一時directoryの絶対pathと `.md` 名 |
| 利用者の発言 | grillの問いに対し、集約の境界は推奨のまま受け入れ、最後に一覧へ合意する |
| 観測1 | 「キャンセル料」が要素一覧に入らず、`## 業務知識へ提案する概念`（または `## 捨てた割り当て` / `## 未決` と区別できる節）に、名前・なぜ要るか・どの業務ルールから導いたか・正式な定義のどの節へ足すべきかが書かれる |
| 観測2 | 報告に同じ提案一覧と、次の一手として `formulate-domain` へ `references` で渡すことが示され、domain-rule資料そのものは書き換えられていない |
| 観測3 | `verify.py` が標準入力の本文で通り、その後に write-doc で保存される。保存前に完了と述べない |
| 観測4 | 問いが一問ずつ推奨付きで6問以下（対話規律の本文はこの入口に無く grill に委ねている） |
| 記録 | 会話の全文、保存された資料、観測1〜4の根拠箇所の引用を `evals/runs/<YYYY-MM-DD>/model-domain-manual.md` に保存する。観測できなかった項目は「未観測」と書き、合否にしない |
